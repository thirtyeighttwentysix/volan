# Volan 1.0.0

**Draft release notes.** Version 1.0.0 is not published. The unsigned 1.0.0-rc.1 rehearsal checks
the implementation described below; the current public library version remains 0.1.0-alpha.2.

Volan generates a typed JVM client from a schema and runs through JDBC on Java 17+.
The planned 1.0 release adds H2, MySQL and MariaDB to PostgreSQL and SQLite, automatic Gradle/Maven
generation, optional coroutines and Micrometer metrics, and a globally installable CLI.

## Changes since alpha.2

- H2, MySQL and MariaDB CRUD, relations, summaries, transactions, schema inspection and migrations.
  Their DDL can commit immediately; interrupted changes retain journal progress and need manual repair.
- CLI `init`, `generate`, `format`, `validate`, `db pull` and `db push`; cross-platform installers
  verify checksums, configure user PATH and support replacement with rollback on activation failure.
- Gradle and Maven plugins generate during an ordinary build, clean up removed models and use the
  matching runtime. Java applications compile the generated Kotlin sources through the Kotlin compiler.
- Optional `volan-coroutines` adds `suspendQuery`, bounded blocking JDBC dispatch, statement cancellation
  and cleanup before coroutine completion. Transaction callbacks remain synchronous on one worker.
- Statement interceptors and optional `volan-micrometer` query count/duration with bounded tags.
- Russian and English Mintlify guides and independent Kotlin, Java, Spring Boot and Ktor examples.
- Forty measured PostgreSQL benchmark cases covering reads, concurrent readers, updates and insert/delete
  transactions. Raw results and configuration are committed; broad write intervals do not support a ranking.

The release contains thirteen library modules, the BOM, Gradle and Maven plugin implementations and
the Gradle plugin marker: seventeen Maven artifacts. JDBC drivers are selected separately.
CLI archives are attached to the GitHub release and contain their JVM dependencies; Java 17+ is required.

## Upgrade

Upgrade the generator/build plugin and runtime together, then regenerate the client.
Use the plugin version explicitly; use `volan-bom` to align the library modules. Alpha.2 projects
with custom generation tasks can replace them with the [build plugins](../build-plugins.md).
The expanded DDL data classes require recompilation of alpha consumers using `DropConstraint.copy`.

Spring examples use Volan's transaction API; Spring `@Transactional` integration is not provided.
The Ktor example dispatches JDBC through `suspendQuery`, rather than running it on request workers.

## Limits

Review [database differences](../dialects.md), [migration guarantees](../migrations.md),
[cancellation semantics](../coroutines-and-observability.md) and
[deferred features](../../ROADMAP.md#deliberately-deferred). Runtime coverage has no 85% gate yet.
Fields named `count` and some Kotlin keywords can still generate uncompilable code; use another
field name with `@map` where needed. Arbitrary database introspection, deeper nested update writes,
cursor paging with explicit ordering and native types outside PostgreSQL remain limited.

Publication verification builds clean consumers from signed staged artifacts, then repeats them
using actual Maven Central downloads before creating the GitHub release. An unsigned branch
rehearsal by itself is not proof of Central publication.
