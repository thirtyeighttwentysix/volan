# Volan 0.1.0-alpha.2

The second Maven Central alpha adds SQLite to Volan's schema-first Kotlin and Java ORM on Java 17+.
PostgreSQL remains supported. APIs and generated source may change during the alpha series.

## What's new

- SQLite dialect discovery, generated CRUD, upsert, bulk writes, relations, nested writes,
  aggregates, paging, asynchronous operations and transactions with savepoints.
- SQLite DDL, introspection, pull/push, structural drift detection and versioned migrations.
  Table rebuilds preserve rows, indexes and AUTOINCREMENT history, validate foreign keys before
  commit and roll back on failure. Concurrent migration writers are serialized.
- SQLite JDBC URLs in the CLI, a documented database feature matrix and SQLite storage conventions.
- The `volan-dialect-sqlite` Maven module and its constraint in the BOM.

Bulk inserts now preserve input order and per-row defaults across different insert shapes,
respect dialect parameter limits and roll back all batches on failure. Relation loading handles
integral JDBC keys and UUID strings consistently. SQLite pools retain private in-memory databases
until the client closes. Build dependencies and CI actions have also been updated.

## Install

```kotlin
repositories { mavenCentral() }

dependencies {
    implementation(platform("io.github.thirtyeighttwentysix:volan-bom:0.1.0-alpha.2"))
    implementation("io.github.thirtyeighttwentysix:volan-runtime")
    implementation("io.github.thirtyeighttwentysix:volan-dialect-sqlite")
    implementation("io.github.thirtyeighttwentysix:volan-migrate")
    runtimeOnly("org.xerial:sqlite-jdbc:3.53.4.0")
}
```

Use `provider = "sqlite"` in the schema and a JDBC URL such as `jdbc:sqlite:./data.db`.
For PostgreSQL, select `volan-dialect-postgres` and the PostgreSQL JDBC driver instead.
Use `volan-codegen:0.1.0-alpha.2` for build-time client generation. Upgrade the generator and
runtime together and regenerate your client.

Published modules: `volan-core`, `volan-schema`, `volan-ir`, `volan-codegen`, `volan-dialect-api`,
`volan-dialect-postgres`, `volan-dialect-sqlite`, `volan-runtime`, `volan-migrate`, and `volan-bom`.

SQLite migrations support ordinary tables in the main database. Decimal, arrays, native `@db`
types and full-text search are unsupported; introspection refuses unsupported database objects
instead of silently omitting them. Enum columns are stored as TEXT and pulled as String.
See the [feature matrix and storage conventions](https://github.com/thirtyeighttwentysix/volan/blob/v0.1.0-alpha.2/docs/dialects.md)
and [migration guarantees](https://github.com/thirtyeighttwentysix/volan/blob/v0.1.0-alpha.2/docs/migrations.md).

MySQL, MariaDB, H2, the coroutine adapter and a Gradle plugin are not included. The CLI can be
built from this tag with `./gradlew :volan-cli:installDist`.

Release verification checks metadata, checksums, signatures and Java 17 bytecode, then generates,
compiles and runs an independent Java client against PostgreSQL and SQLite. The workflow repeats
artifact verification and consumer tests after downloading the release from Maven Central.
